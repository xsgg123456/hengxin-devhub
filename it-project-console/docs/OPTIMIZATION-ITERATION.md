# 2026-09-15 已确认：交付后单节点优化与排期默认值

用户已授权本地正式开发及验证；不包含生产上线。本文覆盖上一版七环节优化预览。

## 验收规则

1. 已完成主项目（含归档）可以提出优化需求；取消或未完成项目不允许。优化需求关联原项目，不能以优化项目再建立多层子项目。原项目状态/交付历史/日期不变。
2. 优化需求沿用需求池、审批、接单与通知链路。必填标题、当前问题、期望效果/验收标准、期望上线日期，附件选填；普通需求仍要求附件。首次正式提交日期自动记录。业务草稿、退回重提、撤回/删除及权限沿用原流程。关联父项目提交后不可更换。
3. 只有现有指定审批人姚泽攀可批准/退回/拒绝；批准指定负责人、优先级和审批确认日期，主工程师接单才立项。拒绝/退回理由必填，幂等/并发保护沿用。工程师可退回评估。
4. 优化项目只有一个“优化交付”执行节点，独立一组计划开始/计划交付日期。状态为优化中、待验收、已完成，退回整改后继续优化。沿用现有指定验收人、交付说明/链接、通过/退回、轮次/历史、通知和权限，不允许工程师自行完成。无方案设计/开发/测试/上线等额外阶段。
5. 主项目卡片和详情原位增加提优化需求、后续优化列表和状态；优化详情可返回原项目。需求池、项目列表可按普通/优化筛选并展示归属；已接单优化进入负载/风险/甘特，主项目保持完成，不重复计入在手。普通项目历史保持兼容。
6. 删除单条优化只删除其需求/项目及所属记录，不影响主项目或其他优化。主项目（及其原需求）有任何关联优化需求或项目时阻止删除，提示先处理关联优化，含并发防护。
7. 项目总览中的项目状态分布、月度人员负载两块图表仅manager角色显示，业务/工程师均隐藏；筛选和五个统计卡片保留，直接接项目明细。
8. 首次打开未排期计划时，每个待执行环节预填3工作日，周一至周五，跳过周末；不处理法定假日/调休。起点为立项评审完成日之后下个工作日；无可靠历史完成日的旧项目以当前上海日期为基准并说明。开始日算第1天，下一阶段接前阶段结束后的下一工作日。优化仅1节点3工作日。
9. 默认只填表单，保存后生效。任何已有计划日期原样保留，不覆盖；手改一个环节不连动其他环节。例：2026-09-11完成，普通五环节9/14–16、9/17–21、9/22–24、9/25–29、9/30–10/2。
10. 替换预览入口为正式权限/数据与原型等价实现，不保留演示身份切换作为正式业务审批入口。附件上传沿用现有组件。

## 接口与数据约定

- Demand、DemoDemand及需求写DTO增加可空 parentProjectId、optimizationOutcome（默认空）；parentProjectId非空即优化需求。description存当前问题。
- Project、DemoProject增加可空 parentProjectId，沿需求在接单时生成，非空即优化项目。普通记录默认空。
- ProjectProposal通过demandId关联需求获取父项目，无需再重复保存。
- 单节点内部复用现有“验收交付”阶段及验收流程，parentProjectId非空时用户可见标签为“优化交付”，remainingStages仅返回该阶段；无其他执行阶段。优化计划上线/交付里程碑均取单节点结束日期，用户只编辑一组起止日期。
- 其他端点沿用，不新建平行审批/验收系统；读模型返还新增字段。

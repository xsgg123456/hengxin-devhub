2026-09-15 用户确认现有前端可点击预览，并授权正式整改。沿用 TASK-TYPE-PREVIEW.md 母版映射及页面布局。本轮开发不自动部署。

## 验收标准
1. 管理待办分为待审批、其他待处理、项目异常；跟进默认折叠且不计入待处理。审批优先于异常，本轮进入审批越早越靠前。正式立项/优化审批/重新评估明确区分；不改变指定姚泽攀审批权限。工程师和业务的职责及可操作事项不被管理分类改动破坏。
2. 正式项目统一 XM 年度编号，项目优化使用 YH 独立年度序列。旧优化 XM 编号迁移为 YH，保存旧编号用于搜索；ID/链接/关联/历史审计保持有效。编号唯一、并发安全、不可日常修改，删除不复用。原型与真实服务规则一致。
3. 卡片、详情、甘特、需求池、审批、接单、进度、计划和验收统一显示正式项目/项目优化。优化顶部显示所属原项目，支持跳转。普通项目七环节，优化仅一个“优化完成验收”节点；内部兼容现有存储阶段，不新增业务环节。
4. 优化状态明确待排期/待开始/优化中/待验收/退回整改/优化已完成/已取消；完成状态由业务验收决定。已完成原项目不因优化重新打开。
5. 甘特增加全部/正式/优化筛选，标签与悬浮信息区分，保留风险颜色语义。未在当月出现的原项目不影响优化展示。计数拆分正式项目和优化。
6. 需求池、审批按钮和成功/失败反馈、消息通知同步类型用语，不再把优化称为正式立项。通知不在开发中实际发送。
7. 当前异常保留；仅存在日期调整历史不独立进入管理待办。单项目异常合并一行。需求显示提出人/部门/本轮等待工作日，无内部UUID。工作日跳过周六日。
8. 统计明确正式和优化数量及合计口径；优化仍计入人员负载。搜索包含新旧编号。保持实时同步、过滤条件、草稿与冲突保护。
9. 预览数据只在 prototype+显式参数注入；production不显示预览字样或示例记录。

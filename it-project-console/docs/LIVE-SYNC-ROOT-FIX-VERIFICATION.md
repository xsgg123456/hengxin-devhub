# 数据联动根治整改验收记录

日期：2026-09-18
范围：本地开发环境；不连接生产数据库，不发送真实钉钉通知，不部署。

## 本轮解决的根因

| 根因 | 修复后的统一规则 | 可观察结果 |
|---|---|---|
| 项目改派后需求仍读取原部门/原提出人 | 需求保留原始提交人；已关联项目的当前部门、业务负责人、当前归属由项目最新记录解析 | 需求列表、详情、提出人/部门分布、筛选和待办使用当前归属；历史仍显示原提交人 |
| 工作区刷新只用“请求完成”判断，竞争请求会丢版本 | 刷新返回 `applied / superseded / failed`；只有真正应用的快照推进同步水位 | 后发失败、前发晚到时不会把旧版本标成已同步；失败有中文重试入口 |
| 今日待办拼接旧 dashboard 与新 workspace | 待办项目和责任判断来自同一工作区；仅在 dashboard revision 相同才采用其等待天数 | 改派、删除、撤回验收后不会继续显示旧待办 |
| 统计与详情没有版本关系 | dashboard 和 demand-statistics 返回工作区版本；查询拒绝不匹配响应并提示重试 | 统计不会静默覆盖当前详情版本 |
| 调岗/资格撤销只拦后端，前端仍显示计划、进度、待办 | API、前端入口、待办生成统一检查账号有效性、工程师资格和项目职责 | 资格撤销后任务消失，页面变只读并提示交接 |
| 风险/立项/分配通知只看入队时快照 | 投递前锁定并重读需求/项目，复核当前收件人、状态、风险版本和风险内容；不适用消息跳过 | 风险解除、归档、改派或人员退出后，不发送旧消息；已受理历史保留 |
| 字段校验和组件异常直出英文 | 字段标签映射和未知错误兜底统一中文 | `parentProjectId is required` 等英文提示不再面向用户出现 |

## 验证结果

- Web 单元测试：55 个文件、335 个测试通过。
- API 单元测试：24 个文件、114 个测试通过。
- API 隔离集成测试：第一阶段 22 个文件、150 个测试；第二阶段 4 个文件、22 个测试，全部通过。新增“工程师调离 IT 后排期/整体进度 403 且无写入”回归。独立 schema 与 Bucket 测试后回收。
- Web/API 类型检查通过。
- Web/API 生产构建通过。
- Playwright 原型全量流程：63/63 条用例通过（单 worker，约 6.6 分钟）；拆分验收动作后，管理/工程师验收与完整阶段验收专项 3/3 通过。
- 本地真实 API＋Web 双账号验收：1/1 通过；覆盖管理指定、工程师提交/撤回/重提、业务退回/通过、刷新持久化，以及“服务端已落库但客户端连接断开”场景。测试使用隔离 schema、MinIO、API、Vite 和 Chromium，未使用生产账号或数据。
- `git diff --check` 通过；仅有换行符提示，没有空白错误。

## 重点对抗场景

1. 项目部门和业务负责人改派：需求列表、深链详情、当前统计口径更新，原提出人不被覆盖。
2. 两个刷新请求反序且后发失败：旧响应返回 `superseded`，同步器补拉并最终应用新版本。
3. 统计响应版本落后：响应被拒绝并给出中文提示，工作区版本一致后才展示。
4. 工程师调离 IT/资格撤销：排期、整体进度、个人进展、项目待办入口同时失效。
5. 风险解除/项目改派与通知 flush 竞态：投递事务先锁定目标行，再重读当前关系和风险快照。
6. 项目删除时验收草稿：草稿保留但显示删除提示并阻止提交。

审查状态：最终独立对抗审查 Stage 1、Stage 2 均通过，未发现高风险功能、安全或一致性阻断；通知主服务已拆至 300 行以内，验收动作已拆出独立 composable。生产发布仍需另行授权。
